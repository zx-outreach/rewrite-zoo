About & conventions

The ZX Rewrite Zoo is a catalogue of rewrite rules for the qubit ZX-calculus and its relatives, the ZH- and ZW-calculus. Each rule records where it first appeared, which fragment it belongs to, and how it relates to other rules.

Semantics and scalars

All diagrams use the semantics of PyZX, which agrees with the conventions of Picturing Quantum Software:

  • A Z-spider with phase $\alpha$ is $|0\cdots0\rangle\langle0\cdots0| + e^{i\alpha}|1\cdots1\rangle\langle1\cdots1|$.
  • An X-spider with phase $\alpha$ is $|{+}\cdots{+}\rangle\langle{+}\cdots{+}| + e^{i\alpha}|{-}\cdots{-}\rangle\langle{-}\cdots{-}|$.
  • A Hadamard gate, drawn as a yellow box in the two-colour view or as a blue dashed Hadamard edge in the graph-like view, is the unitary $\tfrac{1}{\sqrt2}\begin{pmatrix}1&1\\1&-1\end{pmatrix}$. In the data, Hadamard gates in ZX-rules are always stored as Hadamard edges.
  • An H-box in a ZH-rule with label $a$ is the unnormalised tensor with entries $a^{i_1 \cdots i_n}$, following the original ZH-calculus. With label $-1$ (shown without a label) and two legs it is therefore $\sqrt2$ times the Hadamard gate.

A rule with scalar $s$ states that LHS = $s$ · RHS as linear maps, exactly. The scalar is stored in the rule's metadata, not in the diagrams. This lets it depend on the parameters of the rule, such as the phases or the number of legs. Use the Scalar on left toggle to move the scalar to the other side.

Fragments

The fragments are nested. Each one contains all the previous ones:

  1. Phase-free: Z- and X-spiders whose phases are all zero, and no Hadamards.
  2. Pauli: spider phases are 0 or π, still without Hadamards.
  3. Clifford: phases are multiples of π/2, and Hadamards are allowed.
  4. Clifford+T: phases are multiples of π/4.
  5. Universal: arbitrary phases.

A rule is listed under the smallest fragment in which it can be stated. A rule with a free phase parameter $\alpha \in \mathbb{R}$ is therefore universal, even if it is also often used with Clifford phases.

ZH- and ZW-rules are classified in the same hierarchy, according to the smallest ZX-fragment that contains their generators. An H-box with the standard label −1 is a Hadamard (Clifford) when it has two legs, and of Toffoli type (Clifford+T) when it has three or more. A W-node can be built from Clifford+T diagrams. H-boxes and Z-boxes with labels that are not phases make a rule universal. So the phase-free ZH-calculus of the literature ends up under Clifford+T here. The fragment is computed from the diagrams when the site is built, and the build fails if it disagrees with the metadata.

Views and variants

Every ZX-rule can be shown in three views:

  • Two-colour: Z- and X-spiders, with Hadamard gates drawn as boxes.
  • GH: every X-spider is turned into a Z-spider by putting Hadamards on its legs, so there are only Z-spiders, connected by plain or Hadamard edges (blue, dashed).
  • Graph-like: additionally all spiders connected by plain edges are fused, self-loops and pairs of parallel Hadamard edges are removed, and every input and output is connected by a plain wire to its own spider. Rules that become trivial in this form, like spider fusion, have no graph-like view. The scalar is adjusted for the simplifications.

One of the views is drawn by hand; the others are derived automatically and are marked as such.

The following variants of each rule are generated automatically, rather than listed as separate rules:

  • Colour-swapped: swap Z and X. This is available for all ZX-rules.
  • Conjugate: negate all phases and conjugate all labels; the scalar is conjugated as well.
  • Transpose: mirror the diagram, so that inputs become outputs.
  • Adjoint: both of the above.

The build checks every single generated variant, including its transformed scalar.

Rules with any number of legs

Many rules hold for any number of legs, such as spider fusion, or for any number of repeated parts, such as the neighbours in local complementation. These are shown with ⋯ between the repeated parts. On the rule page you can choose a specific number of legs. Every such instance in the offered range is generated and verified separately.

Complete axiomatisations

The completeness pages list, for each completeness result in the literature, all the rules of the complete axiomatisation, with their labels in the paper. Some axioms cannot be represented here, for instance because they use the triangle, the λ-box or the fermionic crossing, or because they state that a bare cup is a spider. These are listed with an explanation.

Some rules in the literature are only a different representation of a rule in the zoo, for instance with the scalar written as a diagram, or the special case needed for one completeness proof. These are listed on the page of the main rule as alternative representations.

Quantum gates

The quantum gates section shows common gates (Paulis, Hadamard, phase gates, CNOT, CZ, SWAP, CCZ, Toffoli, controlled Hadamard and controlled SWAP) as a circuit on the left and as a ZX- or ZH-diagram on the right, with the exact scalar. These are verified against the unitary of the circuit. The diagram can be exported to PyZX; the circuit side can only be exported to TikZ.

Rules that are only drawn

Some rules from the literature cannot be represented in PyZX or ZXLive, for instance because they use the triangle, the λ-box, Backens' star or the fermionic crossing of the ZW-calculus, or because they are about bare cups and caps. These rules are still included, marked not checked. They are drawn (with symbols for the extra generators) and can be exported to TikZ, but they are not verified and cannot be exported to PyZX or ZXLive.

Verification

When the site is built, the two sides of every variant are contracted to matrices with PyZX and compared, scalar included.

  • Symbolic phases are checked at a set of fixed and random values from their domain. Boolean, Clifford and Clifford+T parameters are checked exhaustively when the number of combinations is small.
  • Rules with an arbitrary number of legs are checked for every number of legs offered on the rule page, with the scalar formula evaluated at those numbers. All variants are checked for the default number of legs; the other numbers are checked in every view.

Downloads

  • TikZ: TikZiT files using the styles of Picturing Quantum Software. Download the style file to typeset them.
  • PyZX JSON: the left- and right-hand sides as PyZX graphs (zx.Graph.from_json). The scalar is not included; it is in the metadata.
  • ZXLive: .zxr custom rule files. When the scalar is a number, it is stored in the right-hand side's scalar so that ZXLive's correctness check passes. There is also a zip with all rules that can be used directly as a ZXLive custom-rules folder.
  • Everything: a zip with all rules, including their metadata.

Contributing

Each rule is a directory rules/<id>/ containing:

  • meta.json with the rule's metadata;
  • lhs.json and rhs.json with its PyZX graphs (these can be drawn and saved with ZXLive);
  • optionally, a hand-made version of the other view in alt/.

Running python build.py verifies everything and regenerates the site.
