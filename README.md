# ZX Rewrite Zoo

An interactive catalogue of the known useful rewrite rules of the (qubit) ZX-calculus, ZH-calculus and ZW-calculus.

Each rule comes with:
- its source, i.e. the paper where it first appeared;
- its fragment and its exact scalar;
- a description and the rules it is related to;
- diagrams that can be downloaded as TikZ, PyZX JSON or ZXLive rule files.

The site is static. It is generated by a Python script from the rule data in `rules/`, and every rule, together with all its generated variants, is verified with [PyZX](https://github.com/zxcalc/pyzx) on each build.

## Building

```sh
pip install -r requirements.txt
python build.py              # verify all rules, then write the site to _site/
python build.py --check      # only verify
python -m http.server --directory _site 8000   # preview at http://localhost:8000
python -m pytest             # tests for the tooling
```

The GitHub Actions workflow in `.github/workflows/pages.yml` runs the tests, verifies all rules, builds the site and deploys it to GitHub Pages. In the repository settings, set *Pages → Source* to *GitHub Actions*.

## Layout

| path | content |
|---|---|
| `rules/<id>/` | one directory per rule: `meta.json`, `lhs.json`, `rhs.json` (PyZX JSON), optionally `alt/` |
| `data/groups.json` | the groups in which rules are organised (more in `data/groups-*.json`) |
| `data/zx-papers.bib` | the publication list of zxcalculus.com, used for all references; `data/*.bib` adds and overrides entries |
| `zxrewrites/` | the Python package: loading, verification, variants, export and site generation |
| `authoring/` | the DSL and scripts used to write the initial rule data; see [authoring/README.md](authoring/README.md) for the data conventions |
| `site/` | Jinja2 templates and static assets (CSS, the d3-based diagram viewer) |
| `reference/book/` | the LaTeX/TikZ sources of the cheatsheets of *Picturing Quantum Software*, used as a source of rules |
| `tests/` | pytest tests for the tooling |

## Adding a rule

1. Draw the two sides, for instance in ZXLive, following the conventions in [authoring/README.md](authoring/README.md): inputs on the left, outputs on the right, Hadamard gates as Hadamard edges.
2. Save them as `rules/<id>/lhs.json` and `rules/<id>/rhs.json`.
3. Write `rules/<id>/meta.json`.
4. Run `python build.py --check --only=<id>`. It reports schema problems, a wrong fragment, or a wrong scalar. In that last case it also tells you what the actual scalar is.
